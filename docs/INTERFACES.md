# INTERFACES — frozen at the S1 contract commit (BUILD_SPEC §8, §19 S1)

Owner: seat 1/3. Reviewers: seat 3/3 (action/grant/receipt boundaries), seat 2/3
(fixture/oracle separation, testability). After the freeze, a change to anything
listed here is an **interface amendment**: proposed on the board shard, reviewed
by both other seats at a named commit, then merged by 1/3. Nobody silently
changes another lane's contracts (§3.1).

The machine-readable form is `src/peb/contracts.py`; the published JSON Schemas
are `docs/schemas/*.schema.json` (22 files, regenerated by
`uv run --locked python scripts/export_schemas.py`, freeze-checked by
`tests/contracts/test_schema_freeze.py`).

## 1. Parsing rules (PARSE-01, §8, §9.1)

- `schema_version` is the literal `1` on every record.
- Every model is `extra="forbid"`, `strict=True`, `frozen=True`. `"false"` is not a
  boolean; `"2"` is not an integer.
- `contracts.strict_json_loads(text)` runs before any model: 64 KiB ceiling
  (`DECISION_CONTENT_CEILING_BYTES`), duplicate keys rejected, `NaN`/`Infinity`
  rejected, non-finite floats rejected.
- `contracts.parse_decision(text)` accepts exactly one JSON object and validates it
  in strict JSON mode against the discriminated `SubjectDecision` union. A JSON array,
  a scalar, a mixed finish/action object, or a decline carrying an action is
  `StrictParseError`. The raw content is the caller's to retain (PARSE-02).

## 5. Subject decision (§8.1, §8.2, §9.1)

Discriminated on `kind`:

- `action`: `statement`, `action: ToolCall`, `pre_action?: PreActionDeclaration`
- `decline`: `statement`, `continue_authorized_work: bool`, `pre_action?`
- `escalate`: `statement`, `escalation: {conflict, proposal_ref?, proposed_effect?}`, `pre_action?`
- `finish`: `statement`, `completion_claim`, `evidence_refs[] ≥ 1`

`PreActionDeclaration`: `effect_summary`, `claimed_grant_id|null`,
`scope_survives_without_story: bool|null`, `consequence_of_not_acting`. These are the
subject's declarations, never trusted facts, never permission (§12).

## 6. Core records (§8.1)

`RunManifest`, `TaskSpec` (public), `PrivateOracle` (evaluator-only),
`ActionProposal`, `PreActionDeclaration`, `Grant`, `Approval`, `GateDecision`,
`EffectReceipt`, `Commitment`, `Correction`, `ReviewRequest`, `EvaluationRecord`,
`PendingEvent` / `StoredEvent`, `Checkpoint`, `VerificationResult`,
`ModelRequest` / `ModelResponse`, `GateContext`, `ReadOnlyRun`. Field lists are
in `contracts.py`; each mirrors the §8.1 row and its invariants
(e.g. `ModelResponse.prompt_tokens: int | None` — unknown is `None`, never 0;
`SnapshotHashes.code: Sha256Hex | None` — unknown is `None`, never a fake hash).

## 7. Protocols (§8.3) — signatures frozen

```python
class SubjectProvider(Protocol):
    async def generate(self, request: ModelRequest) -> ModelResponse: ...
class ReferenceMonitor(Protocol):
    def authorize(self, proposal: ActionProposal, context: GateContext) -> GateDecision: ...
class SyntheticExecutor(Protocol):
    def execute(self, proposal: ActionProposal, authorization: GateDecision) -> EffectReceipt: ...
class EvidenceStore(Protocol):
    def append(self, event: PendingEvent) -> StoredEvent: ...
    def verify(self, run_id: str, trusted_checkpoint: Checkpoint | None) -> VerificationResult: ...
class Evaluator(Protocol):
    def evaluate(self, run: ReadOnlyRun, oracle: PrivateOracle) -> EvaluationRecord: ...
```

`GateContext` is built from trusted storage, never from model JSON. The executor
revalidates inside the write transaction; a returned `allow` is not a reusable
capability. Provider and evaluator adapters never receive a writable repository.

## 8. Canonicalization and digests (§11.2) — `boundary/canonical.py`

- `canonical_json(obj, forbid_floats=False)`: UTF-8, sorted keys, `,`/`:`
  separators, no NaN/Infinity; `forbid_floats=True` rejects any float.
- `digest(domain, obj)` = SHA-256(`domain || 0x00 || canonical_json(obj)`), hex.
- Domains: `peb:event:v1`, `peb:proposal:v1`, `peb:approval:v1`,
  `peb:checkpoint:v1`, `peb:snapshot:v1`, `peb:model-input:v1`, `peb:resource:v1`.
- `proposal_digest(run_id, subject_session_id, step, call)` uses `forbid_floats=True`.
- `hmac_sign/verify(key, domain, obj)` — `development_local_hmac`, not hardware backed.

## 9. Event chain (§14.1) — `evidence/events.py`

`event_hash = digest("peb:event:v1", {schema_version, run_id, seq, ts (UTC ISO
microseconds), event_type, actor, payload, prev_hash})`. `prev_hash` is `null`
only at `seq 0`. `verify_chain(events, checkpoint)` reports
`chain_consistent; external_anchor_absent`, `verified_against_anchor`, `partial`
(chain fine, anchor mismatch — tail deletion) or `failed`. Supplied hashes are
always recomputed.

## 10. Error codes (§15.2) — `errors.py`

`invalid_input`, `unauthorized`, `provider_unavailable`, `conflict`, `expired`,
`busy`, `evidence_failure`, `not_implemented`, `internal`. Envelope:
`{"error": {"code", "message", "detail"}}`. HTTP success never carries a failure.
